# 维护非编程内容

先识别最终读者和用途：人类读者需要能完成理解、协作或操作所需的信息；AI 读者需要明确、可执行且上下文足够的指令。只保留该读者在当前有效目标下仍需要的内容。

## 直接编辑为最终状态

“将 A 改为 B”“删除 C”或“恢复默认值”描述的是目标状态，不是应当写入正文的变更过程。直接写入 B、移除 C 或恢复默认内容；不要把“已删除”“由 A 改为 B”“恢复为默认值”等编辑叙述留在交付物中。

编辑时一并清理受影响的文本：

- 已废止的内容、术语、引用、前提和临时说明；
- 重复说明的默认行为或已经由上下文清楚表达的事实；
- 只因旧内容存在而添加、现已失效的“不要”“不得”等否定式残留；
- 与当前有效需求、项目规则或安全边界冲突的用户补充内容。

仅当读者需要审计、迁移、合规记录或理解仍在生效的历史兼容性时，才保留变更历史，并把它放在该类记录应在的位置，而不是混入正文。

## 保留必要约束，而非编辑痕迹

不要为普通替换、删除或恢复默认值补充“不要 X”“不得 Y”。只有在该限制是长期有效的业务、合规、安全或操作边界，且正面描述不足以避免误用时，才保留简洁的否定约束。若被删除的内容失效后，该约束也没有独立价值，应一并删除。

不要因清理而删除无法确认已过期、且可能承载独立业务价值的信息；先依据当前有效需求、相邻内容和项目规则核实，仍无法判断时指出疑点。

## 与其他 Skill 的边界

本 Skill 只决定非编程文本如何面向读者呈现，不决定业务目标、实现或持久文档的归属：

- 新的非简单开发需求先按 `skill:align` 处理；当前任务的内容调整继承已确认模式，纯措辞或明确的小改动不重开对齐；
- 判断业务信息应放在代码、注释还是持久文档，或维护独立 review 需求文档时，按 `skill:code-as-spec` 处理；
- 对已有 diff 查需求符合性和缺陷时，按 `skill:code-review` 处理。

上述 Skill 同时适用时，先由其确定内容边界与有效要求，再用本 Skill 将文本整理为最终状态。

## 完成前检查

重读受影响段落，确认读者只会看见当前有效内容：不存在编辑过程叙述、失效引用、无意义的默认值重复或没有独立价值的否定约束。最终回复遵循适用的输出约定；要求仅交付当前版本时，不额外解释修改过程。
