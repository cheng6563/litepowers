# 维护非编程内容

先识别最终读者、用途和本次修改范围。人类读者需要足够的信息完成理解或操作；AI 读者需要明确、可执行且上下文足够的指令。以目标内容的最新完整版本为起点，结合直接关联的引用和当前要求判断。

## 确定基线与必要偏差

以用户当前明确需求为目标，优先沿用项目已有规范；没有项目规范时，使用能核实的成熟标准或框架官方默认行为。只表达实际需要的偏差和读者完成任务必需的信息，不重复抄写基线。无法确定默认值时先查相关依据，不凭印象编造。

恢复默认时移除相应显式覆盖及多余说明，让基线自然生效。

## 直接编辑为最终状态

直接把原有内容改为目标状态，清除已取消事项及其附属命名、注释、说明和引用，其余目标保持不变。纠偏过程不写成正文说明、产品特性或版本名称；同一事项只保留当前有效表述。

## 主动精简与保留边界

创建或修改内容时，即使用户未要求精简，也检查本次目标及直接关联内容：

- 合并同一作用范围内的同义重复，保留不同前提下确有区别的要求；
- 清理已确认过时或失效的内容、术语、前提和引用；
- 删除基线已覆盖且读者无需单独知道的重复说明，以及随旧内容失效的否定约束。

精简以信息有效性为准，不以字数最少为目标。保留有效需求、必要操作步骤、公开契约与长期业务边界；必要的否定约束仍可保留。审计、迁移、合规或历史兼容用途需要的记录按其用途维护，不混入普通正文。

无法确认价值的信息先核实，仍不确定时保留并指出疑点。用户明确限定只改一处时遵守该范围；范围外发现的精简机会只提出建议。

## 与其他 Skill 的边界

涉及业务目标、实现或文档归属时，按相应 Skill 确定边界：

- 新的非简单开发需求先按 `skill:align` 处理；当前任务的内容调整继承已确认模式，纯措辞或明确的小改动不重开对齐；
- 判断业务信息应放在代码、注释还是持久文档，或维护独立 review 需求文档时，按 `skill:code-as-spec` 处理；
- 对已有 diff 查需求符合性和缺陷时，按 `skill:code-review` 处理。

上述 Skill 同时适用时，先由其确定内容边界与有效要求，再用本 Skill 将文本整理为最终状态。

## 完成前检查

重读受影响内容及引用，核对当前要求是否完整、删改是否真正生效、必要信息是否保留。默认交付整理后的内容或文件位置，不用修改清单代替产物；用户要求报告时另给结果与未决项。
