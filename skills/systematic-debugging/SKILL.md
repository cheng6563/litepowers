# 系统化调试

先恢复原始诉求与已确认上下文，明确触发条件、应发生的业务行为、实际结果及受影响对象；调查期间用它们校准结论和修复方向。用户追问或提醒回看时，沿用原任务检查尚未闭合的因果链，继续已授权的调查。

## 取证与假设

1. 读取完整错误和相关上下文，复现问题；不能复现时先收集能区分假设的证据。
2. 沿调用链或数据流回溯，从症状追到最早偏离预期的位置。日志中的过滤、跳过或调用成功先作为实际执行事实，再核实该条件是否符合业务期望。例如接收人被权限过滤后，还需核实该权限实际控制的功能、目标角色的职责及相关调用方。
3. 用实际记录验证一个具体根因假设，一次只改变一个变量。源码疑点须核对本次输入、分支条件和运行记录是否命中；假设失败时撤销实验，再提出新假设。
4. 用户提供正常场景或其他对照时，比较两者从触发到最终业务效果的关键差异，核实对照是否达到预期。额外入口、重试或补偿可能掩盖共同缺陷；只查到调用成功仍需确认对象、结果及副作用。

查询或连接失败时，判断失败覆盖的证据范围，再尝试已有日志、其他查询入口、本地源码或配置等可用来源。连续三个假设失败时停止试改，重审证据、前提和架构，再选择能减少关键不确定性的调查路径。

## 根因与修复方向

根因结论须能解释本次故障及已提供的关键对照，并区分已证实的因果关系与待验证事项。存在会改变结论的证据缺口且仍有已授权、可执行的取证路径时，继续调查；有效路径均受阻时，报告已尝试路径、缺失证据及最小解除条件。

提出修复方向前，核对它能否恢复原诉求的业务效果，并沿本次已发现的相关入口推演其影响，例如遗漏、重复执行和状态变化。

本 Skill 在诊断期间不修改生产行为。只诊断任务交付根因、证据和必要修复方向。

从只读诊断转入首次修复时，转 `skill:align` 按其入口判断并承接实施，交接原诉求、根因证据、建议方向和待定事项。已有实施合同的任务则返回既定 Approach 继续修复、按 Evidence 验证业务结果及本次改动影响，不因定位完成而结束，也不重新询问测试方式或交付终点。
